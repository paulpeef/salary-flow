# Выпуск Salary Flow

Проверено: 2026-11-01. Код, релизы и лента обновлений находятся в одном публичном
репозитории `paulpeef/salary-flow`. Отдельного репозитория для обновлений нет.
Публичность означает доступность файлов и релизов; она не делает проект скрытым
или доступным только по приглашению.

## Подготовка

1. Сверить `origin/main` и последний релиз на GitHub, прочитать долги в `PROJECT.md`.
2. Поднять значение `VERSION` по умолчанию в `build.sh`, добавить описание
   изменений в `releases/v<версия>.md`. Настройки, журналы, копии пользовательских
   данных и приватный ключ в Git не добавлять.
3. Выполнить `./build.sh`: это также запускает все тесты. На машине владельца
   SDK 27 из Command Line Tools не содержит требуемый `SwiftUIMacros`, поэтому
   рабочая команда — `SDKROOT=/Library/Developer/CommandLineTools/SDKs/MacOSX26.5.sdk ./build.sh`.
   Проверки процессов, окон и RTF должны выполняться вне ограниченной песочницы.
4. Пока проверяется Sparkle, **не устанавливать локально версию с номером нового
   релиза**: сравнение одинаковых номеров не предложит обновление.

## Публикация

После коммита отправить `main`, создать аннотированный тег `v<версия>` и отправить
его в `origin`. Существующий `.github/workflows/release.yml` соберёт приложение
на macOS, упакует его через `ditto`, подпишет архив EdDSA, опубликует релиз
и запишет `appcast.xml` в `main` отдельным коммитом.

Приватный ключ уже хранится в секрете GitHub Actions `SPARKLE_PRIVATE_KEY`.
Не нужно извлекать его или менять ключ при очередном выпуске.

Дождаться успешного завершения всех шагов. Текущий workflow публикует стандартную
инструкцию установки; описание изменений добавляется после публикации:

```bash
gh release edit v1.17 --repo paulpeef/salary-flow --notes-file releases/v1.17.md
git pull --ff-only origin main
```

У токена на этой машине нет права `workflow`: изменение файла Actions отклоняет
push. Обычный выпуск через существующий workflow этого права не требует.

## Проверка результата

Проверить версию, URL, длину архива и подпись в опубликованном `appcast.xml`.
Архив должен проверяться публичным ключом `SUPublicEDKey` из установленного
приложения. После распаковки проверить версию бандла и `codesign --verify`.

В установленной предыдущей версии открыть «Приложение» → «Проверить сейчас».
Отдельно зафиксировать обнаружение обновления и успешную установку после
перезапуска: одно не доказывает другое. Обновить `PROJECT.md` и `JOURNAL.md`
фактическим результатом, синхронизировать документацию с GitHub.
