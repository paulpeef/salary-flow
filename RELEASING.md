# Выпуск Salary Flow

Проверено 2026-11-26. Официальный репозиторий — `paulpeef/salary-flow`.
Релиз для Apple Silicon собирается на Mac владельца из исходников тега.
Закрытый ключ **Salary Flow Local Signing** хранится в пользовательской связке
ключей этого Mac. Отпечаток сертификата SHA-256 —
`a084918dabf0360a9fc93ca8137ea8244ff8f7e509cb3f4e3d51ae3134aef008`.
Утрата ключа потребует перехода на другую подпись и может потребовать повторной
выдачи разрешений клиентами. Ключ Sparkle хранится отдельно в секрете GitHub
`SPARKLE_PRIVATE_KEY`. Приватные ключи и данные встреч не включаются в архив.

## Публикация

1. Сверить `origin/main` и последний релиз. Поднять версию в `build.sh`, добавить
   `releases/v<версия>.md`. Отправить коммит в main и тег этого коммита в origin.
2. На Mac владельца выполнить команду, подставив нужный тег. На этом Mac
   SDK 26.5 содержит SwiftUIMacros, необходимые тестам интерфейса.

   ```bash
   SDKROOT=/Library/Developer/CommandLineTools/SDKs/MacOSX26.5.sdk ./Tools/publish-release.sh v1.19.2
   ```

   Скрипт собирает тег во временной папке, запускает тесты, подписывает
   приложение, проверяет распакованный архив, создаёт черновик релиза и
   передаёт SHA-256 архива в GitHub Actions. Нужен доступ к ключу codesign.
3. Дождаться успешного workflow «Релиз». GitHub проверяет хеш загруженного
   архива, подпись приложения и вложенного кода, точный сертификат, требование
   для будущих обновлений, версию и ключ Sparkle. Затем создаёт и проверяет
   подпись Ed25519 архива, публикует релиз и записывает appcast в main.
   При сбое после создания черновика повторить проверку того же архива через
   `gh workflow run release.yml --ref <тег> -f sha256=<исходный хеш>`.
4. Сверить публичный архив и appcast. После установки обновления проверить версию
   и прежнее разрешение на реальной функции. Открытие окна обновления само по
   себе не подтверждает установку. Не перезапускать приложение во время записи
   или обработки встречи.

Для локальной разработки доступна обычная сборка через `./build.sh`. Без
настроенного сертификата она использует ad-hoc подпись. Публичный релиз
с такой подписью отклоняется. Клиентам не требуется устанавливать сертификат
или менять доверенные корни. При первой установке возможна проверка Gatekeeper.
